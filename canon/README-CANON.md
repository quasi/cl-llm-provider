# Canon Specification

**Infrastructure Version**: 0.1.0

## For Agents

This directory contains a **Canon**—a behavioral specification of the cl-llm-provider system. Use this specification to understand system behavior, generate implementations, or verify existing code.

### What You Can Do

| Task | How |
|------|-----|
| Understand behavior | Read `features/*/scenarios/*.md` for concrete examples |
| Implement feature | Read `features/{name}/contracts/*.md` for interfaces |
| Verify implementation | Compare against `features/*/properties/*.md` for invariants |
| Extend system | Read `core/foundation/vocabulary.md` for domain model |

### Reading Order

1. `canon.yaml` → Features list, metadata
2. `core/foundation/vocabulary.md` → Domain terms (required)
3. `features/{feature}/contracts/` → Interface specifications
4. `features/{feature}/scenarios/` → Concrete behavior examples
5. `features/{feature}/properties/` → Universal invariants

## Artifact Format

All specification files use Markdown with YAML frontmatter:

```yaml
---
type: contract | scenario | property | vocabulary | decision
name: artifact-identifier
version: 1.0.0
feature: feature-name  # omit for core
depends_on:
  - core/vocabulary#TermName
  - features/other/contracts/endpoint
---
```

## Key Concepts

### Vocabulary → Contracts → Scenarios → Properties

```
Vocabulary: WHAT entities exist, their definitions
    ↓
Contracts: HOW to interact with them (interfaces)
    ↓
Scenarios: CONCRETE examples of interactions
    ↓
Properties: UNIVERSAL laws that must hold
```

### Contract Structure

```markdown
## Endpoint: POST /orders

### Preconditions
- {conditions that must be true}

### Request Schema (json-schema)
### Response Schema (json-schema)
### Error Responses (table)
### Side Effects
### Properties
```

### Property Structure

```markdown
## Statement

**For all** {variables}, **if** {preconditions}, **then** {postconditions}.

## Formal Expression (optional)
∀ x ∈ X : P(x) ⟹ Q(x)

## Counterexample Shape
{What violation looks like}
```

### Scenario Structure

```markdown
## Context
{Initial state setup}

## Steps
### 1. {Action}
**Action**: {request/operation}
**Expected**: {outcomes}

### 2. {Next Action}
...

## Verification
ASSERT {condition}
```

## Implementation Notes

- Vocabulary terms MUST be used consistently (no synonyms)
- All contracts reference vocabulary terms
- Properties are **universal** (∀), scenarios are **existential** (∃)
- When sources conflict: code > tests > contracts > comments > docs
